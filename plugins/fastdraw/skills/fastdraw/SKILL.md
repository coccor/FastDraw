# FastDraw

FastDraw diagrams are small text files (`.fdraw`). You place every element yourself; a look file (`.look`) decides how styles are drawn. People edit the same file in a browser editor afterwards.

Run FastDraw's commands as `npx -y fastdraw <command>` (for example `npx -y fastdraw guide`), or as `fastdraw <command>` when it is on the PATH. Below and in the guide they are written `fastdraw <command>`.

1. Save a new diagram in `docs/diagrams/` (create the folder), unless the person names another place or the repo already keeps its `.fdraw` files somewhere. Never at the top of the repo: `fastdraw open` lends the diagram's whole folder to the editor.
2. Run `fastdraw guide` and follow it. It is the single source for the language and the way of working, and it points to `fastdraw guide list` (what each kind of diagram shows), `fastdraw guide <kind>` and `fastdraw sizes`.
   For a diagram of the code, learn the system before choosing anything: every project or service, how each talks to the others (HTTP clients, queues, shared stores, config), and the paths a request or event takes. With several projects, read all of them; if you can hand work to subagents (Explore agents in Claude Code), give each project to one. Do not shrink a big system into a few vague boxes: propose an overview plus one diagram per main path, or the one path the person cares about.
   Choose the kind by what the reader has to understand, not by a word in the request ("request flow" is not a flowchart; "architecture diagram" is said of any system picture). Unless the request names exactly one kind and nothing in it pulls toward another, ask before drawing with your tool for asking a question (AskUserQuestion in Claude Code), your pick first: the kind you would draw and the closest other kind, which path when there are several, and the split when the system is too big for one picture. A request like "request flow architecture diagram" names two and must be asked. If you cannot ask, draw your pick and say what else would have worked.
3. Always finish with `fastdraw check <file>` clean and a look at the PNG from `fastdraw render <file>`.
4. When the diagram is done, always ask the person what to do next, with your tool for asking a question; do not end your turn without asking. The choices: **Open in fastdraw.dev** (run `fastdraw open <file>` in the background, then read its output and give the person the link it prints, in case no browser window appeared; it saves their edits back to the file), **Preview as PNG** (open the rendered PNG in their image viewer) or **Nothing**. Do not open anything before they choose.
5. For a site with light and dark themes, `fastdraw render <file or folder> --dark` writes `x.png` and `x-dark.png` (the look's dark version, Night for the built-in look). Do not copy the file to swap its look line; `--look <name|file.look>` draws with another look. A folder means every `.fdraw` file under it, for `check` too.
6. When a diagram needs vendor icons (Azure, AWS, Google Cloud, Kubernetes, product logos) or a font that does not ship with FastDraw, add them to the look by their https:// address from the recommended sources in `fastdraw guide look` (`icondir "https://.../{name}.svg"`, `icon lambda "https://..."`, `font sans "Inter" "https://..."`), with a fixed version in the address. Do not download icon or font files into the repo unless the person asks for that or the files are not on the web.
7. When changing an existing diagram, do not move, resize or restyle what is already there unless asked. A person may have arranged it by hand.
8. A diagram that already exists as Mermaid (a `.mmd` file or a ```` ```mermaid ```` block in Markdown) is turned into FastDraw with `fastdraw import <file> --dir docs/diagrams`, not redrawn by hand. Treat the result as a first draft: check it, render it and improve the composition as the kind's guide says.
9. For a docs site (a web page, not a GitHub README), put the diagram on the page with `<fastdraw-diagram src="....fdraw">` from https://fastdraw.dev/embed.js, with the rendered PNG inside it as the fallback image. It draws the file live, pannable and zoomable, and follows the page's dark mode.
